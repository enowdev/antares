## Antares v0.8.0

### VPS over Cloudflare Tunnel
- Servers that expose SSH only through a Cloudflare Tunnel (port 22 closed, reached with `cloudflared access ssh`) can now be added on the VPS page. Pick **Cloudflare Tunnel (cloudflared)** under *Connection* and enter the tunnel's hostname; the port is ignored.
- Antares opens the tunnel's WebSocket itself and runs SSH over it, the same carrier `cloudflared` uses, so nothing extra has to be installed where Antares runs. Test, live metrics, processes, `vps_run` and upload/download all work over it, with host-key pinning (TOFU) unchanged.
- Hostnames protected by Cloudflare Access can use an optional **service token** (Client ID + Secret). The secret is encrypted at rest and never returned by the API. Interactive Access login is not supported.
- A refused tunnel says why: Access policy (401/403 or a login redirect), tunnel offline (502/503/504/530), or a hostname not routed to SSH.
- The agent's server list marks tunnel hosts "via cloudflared", and the VPS card shows a *cloudflared* tag.

### Fixes
- A rejected SSH login (direct or tunnel) now names the user, the endpoint and whether a password or private key was tried, so a username left at the `root` default is easy to spot.
- **Test** on a saved server tests what the form shows. Stored credentials and the pinned host key are only used while the form still points at the saved address; after the address changes, the password or key has to be typed again, so saved secrets are never sent to a different server.

- The database migrates to schema version 4 on first start (three new `vps_hosts` columns). Existing servers keep connecting over direct SSH. No configuration changes.
